```prompt Ship my app under several brands
Make an Exact app for each of several brands in this folder, with shared screens and data code. Use https://github.com/expo/exact/blob/main/docs/recipes/white-label.md as the source for each step. The Exact checkout has the same page at docs/recipes/white-label.md.

1. Find the Exact checkout (the folder with scripts/exact.mjs); if you cannot find it, ask me where it is. Ask me for each brand's name, bundle id, platforms, icon, logo, colours, launch picture and URL scheme. If this folder holds an Exact app, ask me whether its screens and data become the shared code.
2. Make this folder a Bun workspace. Put the screens in a package (Contract, and a `.forma` of their tokens) and the data code in a package (TypeScript, with a `.d.ts`). Each brand depends on them as `"workspace:*"`.
3. Make a directory for each brand, with its name and id before the first build: `bun <exact2>/scripts/exact.mjs new <dir> --name "<Name>" --bundle-id <id> --with ios,mac,android` (name the platforms of that brand). A brand is its own app, not a variant.
4. In each brand's app.contract, keep `routes` and the root component, and `use` the screen from the package. A package's component asks only its own package's sources: read each resource in the root and pass its answer as a prop. In app.ts, `export *` from the data package, then export the brand's own `grants`. The shared code exports no `appId`.
5. Give each brand its app.forma (`AccentColor`, and a package token replaced by its full name, as `brand-ui.card`) and its app.json keys: `icons`, `background_color`, `color_scheme_dark`, `protocol_handlers`, and `launchImage` in the `host` entries that `exact new` wrote. Only a brand's own `assets/` ship: pass the logo to the screen as a path.
6. The tests that `exact new` wrote are placeholders: in each brand's app.test.contract, replace them with a test of that brand's first screen.
7. Follow the platform checks in docs/start-here.md (`bun exact.mjs docs platform checks`) for the targets in the app's AGENTS.md and app.json until they pass. Read the reports, including counted findings; a zero exit code alone does not mean clean. Fix the app, not the test. Run the checks in each brand's directory. If a finding stays after three rounds of fixes, or the app had it before you changed anything, record it (step 8) and report it; do not keep trying.
8. When a doc was wrong or missing, or a step needed a workaround, read `bun exact.mjs feedback status`. Under `never`, keep no note. Otherwise record it: `bun exact.mjs feedback note "<what happened>"`, which goes to Expo only as that status says. Do not change the policy; tell me how many notes you kept.
9. Tell me the directory, id and platforms of each brand, and what the tests and checks reported for each. Each id takes its own signing profile and store record, and uploading is mine. Two teams, two Play accounts and store submission have not been run with this layout.
```
