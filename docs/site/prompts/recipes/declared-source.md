```prompt Read JSON from an API in my app
Make the Exact app in this folder read JSON from one endpoint (a GET or a GraphQL query) with a `source` declared in app.contract, and no data module for that read. Use https://github.com/expo/exact/blob/main/docs/recipes/declared-source.md as the source for each step. The Exact checkout has the same page at docs/recipes/declared-source.md.

1. If this folder is not an Exact app (it has no exact.mjs and app.contract), stop and tell me.
2. If I did not give the endpoint's URL and the fields the app shows, ask me; do not invent a URL. If the read needs token refresh, pagination, an offline queue, an overlay, a stream or an upload, stop and tell me: that work stays in app.ts.
3. In app.contract, declare a `shape` for the fields the app reads, and a `source` with a `url` and a `pointer` to the answer in the reply (`/data/items/0`). Write the origin out before any `{param}`: the origin is the grant, so add no `grants` line.
4. Read the source as a `resource`. Draw a message and a Try Again button that runs `refresh` while `failed(now)`, and a `progress` while `not current(now)`. An absent `option` field is `none`; any other missing field fails the read with `shape`. Rename a field in a `derive`.
5. For a GraphQL query, give the source a `graphql` line with the query, and point at the data: `pointer "/data/repository"`. A `send` takes `method "POST"` and `body json`; `graphql` takes neither.
6. If the request needs a token, write the header as the recipe does (`header "Authorization" "Bearer {secret:github.token}"`, with my secret's name), and add `secret.keep github.token`, with that name, to the grants in app.ts. Never write the token's value in a file. On the web that store is origin-readable: for refresh and session tokens, tell me and follow docs/recipes/web-sessions.md.
7. Add a test in app.test.contract that expects what the screen shows when the read fails, and after Try Again. The recipe has no test: take the steps that fail a fetch from docs/recipes/fetch-loading-error.md.
8. Follow the platform checks in docs/start-here.md (`bun exact.mjs docs platform checks`) for the targets in the app's AGENTS.md and app.json until they pass. Read the reports, including counted findings; a zero exit code alone does not mean clean. Fix the app, not the test. If a finding stays after three rounds of fixes, or the app had it before you changed anything, record it (step 9) and report it; do not keep trying.
9. When a doc was wrong or missing, or a step needed a workaround, read `bun exact.mjs feedback status`. Under `never`, keep no note. Otherwise record it: `bun exact.mjs feedback note "<what happened>"`, which goes to Expo only as that status says. Do not change the policy; tell me how many notes you kept.
10. Tell me the source, its origin and its fields, and what the tests and checks reported. Tell me what I must still do by hand: while a secret is absent, nothing is sent and the read fails with `refused`.
```
