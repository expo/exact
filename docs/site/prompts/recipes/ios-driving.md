```prompt Check my app's screens on iOS
Drive the Exact app in this folder on the iOS simulator: visit each screen, check it, and compare it with a reference picture when I give one. Use https://github.com/expo/exact/blob/main/docs/recipes/ios-driving.md as the source for each step. The Exact checkout has the same page at docs/recipes/ios-driving.md.

1. If this folder is not an Exact app (it has no exact.mjs and app.contract), stop and tell me.
2. If I did not say which screens to visit, list the app's routes, sheets and alerts, and ask me. If I gave no reference pictures (the original's screenshots, a design), ask me whether I have them and where they are. An iOS simulator needs macOS: on another system, stop and tell me.
3. Visit each screen with `bun exact.mjs agent ios "<op>" "<op>"`. Drive controls by `testId`. `type <root> <path>` opens a route (`<root>` is the testId of the `navigate=` node). `back` closes an alert or a sheet, or pops a screen. Put `clock data` after an op whose reply the next op reads, and `clock settle` after a transition.
4. On each screen, run `check both`. It says what is wrong: clipped text, a covered control, a small target, low contrast. Fix each finding in the app.
5. For each reference, add `--touch platform`, then take `"screenshot .exact/<name>.png compare ref/<name>.png"` after `clock settle`. It reports the differences by node, and `<name>.diff.png` draws the reference, the screen and the differences. A drive that compares starts its store empty. Tell me each difference before you change a screen to match.
6. With `--touch platform`, real taps reach menus, tabs, alert buttons and native module controls. To open a context menu, hold `tap <source> drag 0 0 press 1000`, then `clock settle`, then select with `tap <action>` and `clock settle` again. A menu row scrolled out of view takes a drive without the flag.
7. Follow the platform checks in docs/start-here.md (`bun exact.mjs docs platform checks`) for the targets in the app's AGENTS.md and app.json until they pass. Read the reports, including counted findings; a zero exit code alone does not mean clean. Fix the app, not the test. End with `bun exact.mjs verify ios`: UIKit bars, light and dark, and a relaunch. If a finding stays after three rounds of fixes, or the app had it before you changed anything, record it (step 8) and report it; do not keep trying.
8. When a doc was wrong or missing, or a step needed a workaround, read `bun exact.mjs feedback status`. Under `never`, keep no note. Otherwise record it: `bun exact.mjs feedback note "<what happened>"`, which goes to Expo only as that status says. Do not change the policy; tell me how many notes you kept.
9. Tell me each screen you visited, what `check` found and what you fixed, each difference from a reference, and what the tests and verify reported. The screenshots are in `.exact/`.
```
