Make a node in the Exact app in this folder something a person can lift and drop into another app (Messages, Notes, Photos, Files). Use https://github.com/expo/exact/blob/main/docs/recipes/drag-out.md as the source for each step. The Exact checkout has the same page at docs/recipes/drag-out.md.

3. In app.contract, give the node `draggable=true` and `dataTransfer=DataTransfer(text=, url=, files=[…])`, with at least one of the three. Each attribute needs the other. Put `draggable` on a box (`view`, `column`, `row`, `box`), a `link`, a `button` or an `image`: not on a run of text, and not inside a grouped list (`list appearance="auto"`).
4. Write `url` as an absolute `http:` or `https:` URL, never an app path. Write a file the app ships as an `image` names one (`assets/photos/7.jpg`). 7. Follow the platform checks in docs/start-here.md (`bun exact.mjs docs platform checks`) for the targets in the app's AGENTS.md and app.json until they pass. Read the reports, including counted findings; a zero exit code alone does not mean clean. Fix the app, not the test. A file or `url` the runner refuses is journaled as `drag: refused: …`, and `tree` shows what it admitted. If a finding stays after three rounds of fixes, or the app had it before you changed anything, record it (step 8) and report it; do not keep trying.
8. When a doc was wrong or missing, or a step needed a workaround, read `bun exact.mjs feedback status`. Under `never`, keep no note. Otherwise record it: `bun exact.mjs feedback note "<what happened>"`, which goes to Expo only as that status says. Do not change the policy; tell me how many notes you kept.
9. Tell me which nodes drag and what each carries, what the tests and checks reported, and that I must try the drop into another app by hand: a press held on the node lifts it on iOS and Android, and a mouse drags it on the Mac.
