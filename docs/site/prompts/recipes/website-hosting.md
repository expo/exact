```prompt Host my website
Build the Exact website in this folder, serve it, and make it ready for its host, at the origin's root or below a path. Use https://github.com/expo/exact/blob/main/docs/recipes/website-hosting.md as the source for each step. The Exact checkout has the same page at docs/recipes/website-hosting.md.

1. If this folder is not an Exact app (it has no exact.mjs and app.contract), stop and tell me.
2. Ask me where the site runs: on Exact's own server or on a static host, and at the origin's root or below a path such as `/app/`. Ask me whether other sites share the origin. The upload to the host is mine to do: publish nothing without asking me.
3. Build with `bun exact.mjs web-build --out dist`, then serve with `bun exact.mjs serve dist`: it serves on 127.0.0.1:8765 (`--port`, else `PORT`) and rebuilds edits. For API pages, start `bun server.ts` or set `API_BASE_URL`.
4. For a path, set `"host": { "web": { "base": "/app/" } }` in app.json with my path, then rebuild. The base starts and ends with `/`. If the app has a Rust renderer, use `--render js`. The wasm target, the signed update store (`deploy` and baked plans), auth callbacks and the web/native dev loop require `/`: if the app needs one of them, stop and tell me.
5. Keep each route pattern and location app-relative: do not write the base in a route, in `path` or in `push`. A route named `/app/item` opens at `/app/app/item`. In `host.web.head`, use `./assets/` paths for bundled files, and absolute URLs for destinations outside the site.
6. For a static host, read its file and fallback rules in `serve --help`. List for me what to upload: `dist/` mounted at the base, the hidden `.exact/` assets too, and the generated `robots.txt` and `.well-known/` files at the origin root as well. On a shared origin, these merge with the existing policies: show me both and ask.
7. Build again, serve the build, and request the base chosen in step 2. For a non-root base, also check that the same path without its trailing slash redirects to the base, and that `/` returns 404. Then run `bun exact.mjs verify` until it passes. Read the reports, including counted findings; a zero exit code alone does not mean clean. Fix the app, not the test. If a finding stays after three rounds of fixes, or the app had it before you changed anything, record it (step 8) and report it; do not keep trying.
8. When a doc was wrong or missing, or a step needed a workaround, read `bun exact.mjs feedback status`. Under `never`, keep no note. Otherwise record it: `bun exact.mjs feedback note "<what happened>"`, which goes to Expo only as that status says. Do not change the policy; tell me how many notes you kept.
9. Tell me the build and serve commands, the base, what verify reported, and what I must still do on the host. A native binary needs a rebuild when the base or the origin changes.
```
