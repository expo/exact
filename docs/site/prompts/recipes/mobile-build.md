```prompt Make a release build for a phone
Make a release build of the Exact app in this folder for an iPhone, the iOS Simulator or Android. Use https://github.com/expo/exact/blob/main/docs/recipes/mobile-build.md as the source for each step. The Exact checkout has the same page at docs/recipes/mobile-build.md.

1. If this folder is not an Exact app (it has no exact.mjs and app.contract), stop and tell me. Find the Exact checkout (the folder with scripts/exact.mjs); if you cannot find it, ask me where it is.
2. If I did not say which build, ask me: the iOS Simulator, a signed iPhone, an unsigned device app, an Android APK or an Android App Bundle. For a signed iPhone, ask me for the team id and the UDID of the phone. For an App Bundle, ask me to set `EXACT_KEYSTORE` (a file path), `EXACT_KEYSTORE_PASSWORD`, `EXACT_KEY_ALIAS` and `EXACT_KEY_PASSWORD` in the environment you run in. Never write one of them into a file in this folder.
3. Before a first build, run `bun <exact2>/scripts/exact.mjs setup --check --platform ios` (or `android`). Tell me what it lacks before you install anything.
4. A production build with updates needs `deploy.signing.keys`, and `EXACT_UPDATE_RECEIPT` or `EXACT_UPDATE_GENESIS=1` (a new stream): ask me which. Without updates, `deploy.store.ios` is `"0"`. Ask me before you change `deploy` in app.json.
5. For a store upload, ask me for `EXACT_VERSION` and `EXACT_BUILD_NUMBER` and export both before building. The build number rises with each upload.
6. Run the command for that build. Simulator: `bun exact.mjs ios --release --no-install --json`. Signed iPhone: `DEVELOPMENT_TEAM=<team-id> bun exact.mjs ios --device --phone <udid> --release --no-install --json`. Unsigned: `bun exact.mjs ios --device --release --unsigned --json`. APK: `EXACT_UPDATE_TRUST=production bun exact.mjs android --release --no-install --json`. App Bundle: `bun exact.mjs android --bundle --json`. With `--json`, add no `--run`, `--prebuild` or `--test`. If a build names `--write-locks`, run it once and keep the files it generates.
7. Read the one JSON object the build prints: `path`, `target`, `trust` and (Apple) `signing`, or `code` and `error` for a failure. The logs are on stderr. Report any build failure that predates your changes or persists after three rounds of fixes, and record it as in step 8.
8. When a doc was wrong or missing, or a step needed a workaround, read `bun exact.mjs feedback status`. Under `never`, keep no note. Otherwise record it: `bun exact.mjs feedback note "<what happened>"`, which goes to Expo only as that status says. Do not change the policy; tell me how many notes you kept.
9. Tell me the command you ran and the artifact's `path`, `trust` and `signing`. The build uploads nothing to a store: that is mine to do. If no profile covers the app and the phone, I must use Xcode's automatic signing for that bundle id and team.
```
