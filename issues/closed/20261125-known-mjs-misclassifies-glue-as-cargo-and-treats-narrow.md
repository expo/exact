# known.mjs misclassifies glue as cargo and treats narrow/unrelated checks without covers as whole-repo passes

**Status:** Closed
**Resolution:** Anchor kindOf on subcommands, split xctest-ios and xctest-macos, match lane note checks by explicit whole/partial allowlists in known.mjs, and emit covers for narrow Bun/Cargo checks in async.mjs.
**Systems:** scripts/known.mjs, scripts/async.mjs
**Author:** Gemini 4 Neon
**Date:** 2026-11-25
**Severity:** P2
**Related:** LLP 1184 (Fail-open defaults)

Verification: verified by running.

At `9c0431fd5`, `scripts/known.mjs:39-45,91-98,105-121` and `scripts/async.mjs:106-113,161-179,201-217,243-297` combine three classification and coverage defects that cause `known.mjs` to mislabel failures as `new` (when their suite never ran) or `unknown` (when it did):

1. **`glue` is misclassified as `'cargo'`.** `kindOf()` (`scripts/known.mjs:39-45`) tests `/\bcargo\b.*\btest\b/` before `/\bbun\b.*\btest\b/`. `glueTests()` (`scripts/async.mjs:106-113`) includes `./scripts/cargo-checkout.test.mjs` and `./scripts/cargo-rustflags.test.mjs`, which are embedded in `glue`'s shell command (`scripts/async.mjs:269-275`). Because `cargo-checkout.test.mjs` matches `\bcargo\b.*\btest\b`, `kindOf(glue.command)` returns `'cargo'` whenever `glue` runs whole or selects either file. Thus `glue` never counts for `known.mjs -- bun test ...`, while a full `glue` pass (`covers` omitted) satisfies `ran()` for `kind === 'cargo'` even when `test` stopped early (`complete: false`) or was skipped.
2. **Narrow/unrelated checks with `covers === null` are treated as whole-repo passes.** `classify()` (`scripts/known.mjs:107-108`) treats `!c.covers` as whole-repo coverage for `kind`. In `scripts/async.mjs:201-217`, `covers()` returns `null` for every check outside `default-test`, `test`, `lane`, `ios`, `macos`, `other-glue`, `glue`, and `conform*` (and returns `null` for every check except `default-test` on full runs). Meanwhile `kindOf()` matches many narrow or unrelated checks:
   - `kind === 'bun'`: `game-vocab` (`async.mjs:247`), `game-pins` (`bun game/app/shells.mjs --test`, `:248`), `game-scaffold` (`:91,250`), `game-assets-scaffold` (`:251`), `web-build-test` (`:278`), `notifications-web` (`bun packages/notifications/test/drive.mjs web`, `:285`), `web-ax-test` (`:289`), `other-glue` on full runs (`:203`), and all 74 `app:<app>:<host>:<n>` steps (`bun scripts/agent.mjs ... --test ...`, `:168-178`).
   - `kind === 'cargo'`: `game` (`game/Cargo.toml`, `:92,245`), `game-recipes` (`exact-game --doc`, `:246`), `cargo:exact-shader-uniforms` (`:163-166`), and `lane` (`-- --ignored ...` only, `:254`, which omits `covers` on full runs and emits `cargo:<pkg>` on partial runs at `:204` despite running only `--ignored` tests).
3. **`macos` and `ios` XCTests are conflated.** `kindOf()` (`scripts/known.mjs:40`) maps both `macos` (`build.mjs --test`) and `ios` (`build.mjs --test --ios`) to `'xctest'`, and `LANE_CHECK.xctest` (`scripts/known.mjs:91`) is hardcoded to `'ios'`. A whole `macos` pass therefore satisfies `ran()` for `ios` failures (and vice versa), while `suitesOf()` (`scripts/known.mjs:95-98`) tags local macOS XCTest failures as `xctest:ios:<Class>`, missing partial `macos` notes (`xctest:macos:<Class>`, `scripts/async.mjs:206-209`) and colliding with partial `ios` notes.

**Trigger.** Run `bun scripts/known.mjs -- cargo test -p <pkg>`, `bun scripts/known.mjs -- bun test <file>`, or `bun scripts/known.mjs -- bun host/apple/build.mjs --test [--ios]` against `refs/notes/async` notes produced by `scripts/async.mjs` (partial or full runs).

**Actual vs. expected.** Unrelated local Cargo or Bun failures are reported as `new` (instead of `unknown`) whenever a narrow check like `game`, `game-vocab`, `web-ax-test`, `notifications-web`, `app:*`, or a full `glue` completed; local Bun failures are reported as `unknown` against a full `glue` note; iOS failures are reported as `new` against a macOS-only full note; and macOS failures fail to match partial macOS notes. Expected per `scripts/known.mjs:7-14,100-104` and `docs/testing.md:68-75` (LLP 1146 D1): only a whole check of the matching suite/platform or a partial check whose `covers` includes the failure's suite may produce `known`/`new`; otherwise the verdict must be `unknown`.

**Verification & siblings.** Verified by running read-only Bun probes against `scripts/async.mjs` and `scripts/known.mjs` at `9c0431fd5`:
- `glueTests(process.cwd()).filter(f => /\bcargo\b/.test(f))` returned `["./scripts/cargo-checkout.test.mjs", "./scripts/cargo-rustflags.test.mjs"]`; `kindOf(fullGlueCmd)` returned `"cargo"`.
- On a full selection, 90 checks matched `kindOf !== null`, including 74 `app:*` checks (`bun`, `covers: null`) plus `game`, `game-recipes`, `cargo:exact-shader-uniforms`, `game-vocab`, `game-pins`, `game-scaffold`, `game-assets-scaffold`, `web-build-test`, `notifications-web`, `web-ax-test`, `other-glue`, `glue` (`cargo`), `ios`, and `macos` — all with `covers: null`.
- Running `classify()` against a partial `game/vocab.test.mjs` note misclassified both `local: -p exact-linux --lib foo::bar` (cargo) and `bun:apps/agents/app.test.ts` (bun) as `new`; against a note with `test` incomplete (`complete: false`) and full `glue` complete, it classified the cargo failure as `new` and a bun failure as `unknown`; against a `macos`-only full note, it classified an `ios` failure as `new`; and `suitesOf` tagged a macOS failure as `['xctest:ios:Nav']`, returning `unknown` against a partial `macos` note covering `['xctest:macos:Nav']`.
Checked sibling consumers of `covers`/`owners` in `scripts/async.mjs` (`retainSkippedFailures:407-420`, `owners:426-449`, `failureSelection:637-657`, `failureAffected:671-681`) and `scripts/async-bisect.mjs`: those match by check name rather than `kindOf`, and `owners` already emits distinct `xctest:ios:<Class>` vs `xctest:macos:<Class>` ids.

**Suggested fix & regression test.** In `scripts/known.mjs`, distinguish `xctest-ios` vs `xctest-macos` (based on `--ios` in `command` / `--kind`), match checks in a note by check name (or explicit whole-suite allowlist: `test` for `cargo`, `glue` for `bun`, `ios` for `xctest-ios`, `macos` for `xctest-macos`, plus exact-`covers` checks like `default-test`, `other-glue`, `cargo:*`, `game`, etc.) rather than regex-guessing `kindOf(c.command)` over every check in the note, and anchor `kindOf()` for local CLI commands on the executable/subcommand (`cargo test`, `bun test`, `build.mjs --test`) so test file names cannot hijack classification. In `scripts/async.mjs`, ensure narrow checks (`game`, `game-recipes`, `cargo:*`, `game-vocab`, `game-scaffold`, `game-assets-scaffold`, `web-build-test`, `web-ax-test`, `other-glue` on full runs) either emit exact `covers` or are excluded from whole-kind matching, and do not give `lane` (`--ignored`-only) normal `cargo:<pkg>` coverage. Add regression tests in `scripts/known.test.mjs` using real `checks()` + `covers()` outputs from `scripts/async.mjs` (full `glue`, partial `game/vocab.test.mjs`, incomplete `test` + passing `lane`/`glue`, and `macos` vs `ios` XCTests).
