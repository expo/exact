# @exact/background (Apple & Android): frozen epochAtZero over sleep-pausing monotonic clocks permanently drops Android WorkManager sync retries and repeatedly defers iOS BGTask retries across device sleep

**Status:** Closed
**Resolution:** Used live wall time outside agent mode in Apple and Android BackgroundModule (converting Apple wake targets via the live offset and re-enqueuing early Android sync wakes) so device sleep does not drop or drift sync retries.
**Systems:** packages/background (Apple BGTaskScheduler/WakeStore, Android WorkManager)
**Author:** Gemini 4 Neon
**Date:** 2026-11-25
**Severity:** P1
**Related:** LLP 1184 (Out of order)

Verification: verified by reading.

At `9c0431fd5`, `BackgroundModule` on both Apple (`packages/background/apple/Background.swift:42, 55, 148-166, 214-228`) and Android (`packages/background/android/Background.kt:59, 142, 184-187, 229-237, 275-284`) anchors `epochAtZero` once at initialization against `context.now()`, whose underlying clocks pause while the device sleeps.

### Reachable trigger
1. An app registers a `sync` tag (`registerSync(tag="outbox")`) whose first attempt fails and re-registers itself, setting `r.notBefore = now() + 300_000` ms (5-minute backoff) and scheduling a WorkManager `OneTimeWorkRequest` (`initialDelay = 300_000 ms`) on Android or `BGAppRefreshTask`/`BGProcessingTask` (`earliestBeginDate = now + 5m`) on iOS.
2. The device enters sleep / Doze for at least 5 minutes while the app process remains alive (suspended in RAM on iOS, cached in memory on Android).
3. The OS scheduler wakes the process after the 5-minute wall-clock deadline has passed: WorkManager invokes `BackgroundWorker.doWork()` -> `module.ran("sync", tag)` on Android, or `BGTaskScheduler` invokes `WakeStore.arrived` -> `BackgroundModule.woke(_:)` on iOS.

### Actual vs. expected result
- **Why `now()` lags:** Outside agent mode, `context.now()` reads `CACurrentMediaTime()` (`mach_absolute_time()`) on Apple (`host/apple/Sources/ExactKit/Session.swift:62-63, 650`, `SessionTime.swift:28-31`) and `std::time::Instant::now()` (`CLOCK_MONOTONIC`) on Android (`host/painted/src/canvas/jni_extensions.rs:28-30, 183-188`, `host/painted/src/canvas/clock.rs:23-25`). Both monotonic clocks stop advancing while the device sleeps. Because `epochAtZero` is computed once in `init` (`Background.swift:55`, `Background.kt:59`), `now() = epochAtZero + context.now()` falls behind real wall time by the cumulative sleep duration (and by any system clock change).
- **Android actual (permanent WorkManager job loss):** `BackgroundModule.ran()` (`Background.kt:234`) evaluates `kind == "sync" && (r.notBefore ?: 0.0) > now()`. Because `now()` did not advance during sleep, `r.notBefore > now()` is still `true`, so `ran()` calls `done(true)` without raising the sync event or re-enqueuing work. `BackgroundWorker.doWork()` (`Background.kt:283`) sees `completed == true` and returns `Result.success()`, permanently deleting the unique WorkManager job while leaving the tag stranded in `tags["sync"]` (and `Handler.postDelayed` at line 207 uses `uptimeMillis()`, which also pauses during sleep, so once the cached process is reclaimed no background retry ever runs).
- **Apple actual (repeated deferral across sleeps):** `WakeStore.take()` (`host/apple/Sources/ExactWakeCarriers/Wakes.swift:83, 215-221`) uses live `Date()`, sees the request is due, removes it from the store, and delivers it to `BackgroundModule.woke(_:)` (`Background.swift:216-228`). `woke(_:)` filters `($0.value.notBefore ?? 0) <= now()` using the lagged `now()`, finds `unique.isEmpty`, and calls `ask(); return wake.done(success: true)`. In `ask()` (`Background.swift:150`), `at = max(soonest, now()) - epochAtZero` is still ~5 minutes ahead of `context.now()`, and `host/apple/modules/ExactExtensions.swift:508` converts that to wall time via `at - module.now() + Date().timeIntervalSince1970 * 1000`, pushing `earliestBeginDate` another ~5 minutes past the live wall clock on every sleeping wake. The same `due(r) - epochAtZero` calculation at `Background.swift:159` also pushes `periodicsync` wakes forward by the cumulative sleep duration whenever `ask()` runs, and `registered`/`lastRun` timestamps lag by cumulative sleep on both platforms.
- **Expected:** Outside agent mode, persisted epoch timestamps and deadlines (`notBefore`, `due`, `registered`, `lastRun`) must be evaluated against the live wall clock (`Date().timeIntervalSince1970 * 1000` / `System.currentTimeMillis().toDouble()`), matching `WakeStore.now()`, `host/apple/Sources/ExactKit/SessionTime.swift:26-33`, and `packages/background/web/index.js:57, 70, 88`, so a sync retry due after device sleep runs when WorkManager or `BGTaskScheduler` wakes the app.

### Verification and sibling sweep
- **Verification:** Verified by reading the complete clock, scheduling, and wake-delivery paths on Apple (`Background.swift`, `Session.swift`, `SessionTime.swift`, `ExactExtensions.swift`, `Wakes.swift`) and Android (`Background.kt`, `Extensions.kt`, `jni_extensions.rs`, `clock.rs`). No hardware sleep run was executed. Note that closed issues `20261110-apple-date-lags-after-sleep-or-a-clock-change.md` and `20261111-linux-android-windows-date-lags-after-sleep-or-a-clock-change.md` fixed host `exactTime` updates across sleep, and `20261110-android-background-keeps-session-clock-times-across-launches.md` copied Apple's frozen `epochAtZero` into `Background.kt`, leaving both background modules vulnerable.
- **Siblings checked:** `packages/background/web/index.js:57, 70, 88` uses `Date.now()` directly. All other packages persisting or comparing epoch timestamps (`packages/purchases/apple/Purchases.swift:48`, `packages/alarms/apple/Alarms.swift:146`, `packages/alarms/android/AlarmRing.kt:86, 157, 188`, `packages/notifications/android/Later.kt:56`, `packages/notifications/apple/Notifications.swift:119`, `packages/pedometer/android/Pedometer.kt:132`, `packages/pedometer/apple/Pedometer.swift:28`) read live wall time directly outside agent mode; only `packages/background/{apple,android}` freeze `epochAtZero`.

### Suggested fix and regression test
- **Android (`Background.kt`):** Outside agent mode, define `now()` as `if (context.agent) epochAtZero + context.now() else System.currentTimeMillis().toDouble()`. Also guard `ran()` against returning `done(true)` when a sync is still in backoff — if `notBefore > now()`, either re-enqueue with the remaining delay or return `done(false)` only when appropriate rather than silently dropping a still-pending tag.
- **Apple (`Background.swift`):** Define `now()` as `context.agent ? epochAtZero + context.now() : Date().timeIntervalSince1970 * 1000`, and in `ask()` convert epoch targets to session-clock `at` using the live offset (`context.now() + (target - now())`) rather than subtracting the init-time `epochAtZero`, so `ExactExtensions.swift:508` reconstructs the exact epoch deadline without adding cumulative sleep time.
- **Regression tests:** Extend `packages/background/test/android/BackgroundTest.kt` and `packages/background/test/apple.mjs` (`overlappingWakes`) with a sleep-simulation test where wall time (`SystemClock.setCurrentTimeMillis` / injectable wall clock) advances by 6 minutes while `context.now()` stays frozen, asserting that `ran("sync", "outbox")` / `woke(syncWake)` raises the due sync instead of returning early or rescheduling 5 minutes further ahead.
