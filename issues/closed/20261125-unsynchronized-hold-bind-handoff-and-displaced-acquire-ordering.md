# Unsynchronized hold/bind handoff and displaced/acquire ordering cause double displacement and an orphaned dead socket in exactListen

**Status:** Closed
**Resolution:** Serialized per-path hold checks with bind/unpublish/look operations under an in-process publication lock and reconciled Loop::turn displaced and acquire signals against hold.holding().
**Systems:** exact-listen (Unix domain socket listener used by exactListen)
**Author:** Gemini 4 Neon
**Date:** 2026-11-25
**Severity:** P2
**Related:** LLP 1184 (Mid-flight cancellation and teardown)

Verification: verified by reading.

At `9c0431fd5`, `exact-listen` has two related synchronization bugs between in-process hold transitions (`host/listen/src/hold.rs:66-124`) and socket publication/displacement (`host/listen/src/lib.rs:274-356, 439-445`, `host/listen/src/bind.rs:249-297`):

1. **Unsynchronized `hold::enter` -> `bind::publish` handoff (`lib.rs:274-283`):** `Loop::run` calls `hold::enter`, releases `HOLDS` (`hold.rs:68-97`), and then calls `self.bind(false)` or `self.bind(true)` without verifying `self.hold.holding()` or serializing publication with `HOLDS`. Although `bind::publish` takes an exclusive `flock` on `<path>.lock` (`bind.rs:251`), that lock is only acquired after `HOLDS` is unlocked.
2. **Wrong `displaced`/`acquire` ordering and missing `holding()` guard in `Loop::turn` (`lib.rs:439-445`):** `signal.displaced.swap(false)` is checked and cleared at lines 440–442 *before* `signal.acquire.swap(false)` at lines 443–445, and line 444 calls `self.bind(false)` unconditionally without checking `self.hold.holding()`.

**Triggering sequences:** Entry point is `exactListen("unix:<path>", { takeover: ... })` -> `host/executor/src/stream.rs:93-95` -> `host/executor/src/listen.rs:190-241` -> `exact_listen_open` (`host/listen/src/abi.rs:92-125`) -> `Listener::open` (`host/listen/src/lib.rs:141-170`), which runs each listener's `Loop::run` on its own OS thread.
- **Sequence 1 (concurrent `takeover: true` opens):** Listener A calls `hold::enter` (`Start::Bind`, `HOLDS = [A]`) and pauses before `self.bind(false)`. Listener B (`takeover: true`) calls `hold::enter`, sets `A.signal.displaced = true`, pushes itself (`HOLDS = [A, B]`), gets `Start::TakeOver`, and runs `self.bind(true)` -> publishes `inode_B` at `path` and watches the parent directory. A then runs `self.bind(false)` -> `bind::publish(path, /*takeover=*/true, /*over=*/false)` (`bind.rs:253-276`), detects B's live socket (`Found::Live`), and `rename`s `inode_A` over `inode_B`. On A's first `turn()` (`lib.rs:440`), A consumes `displaced = true` and calls `self.displace()` (`lib.rs:323-329`), which calls `bind::forget` and drops A's `UnixListener` without unlinking `inode_A`. B's directory watcher triggers `look()` (`lib.rs:333-356`), sees `identity(path) == Some(inode_A) != Some(inode_B)`, and hits `Some(_) => self.displace()` (`lib.rs:351`), dropping B's `UnixListener`. (If A had `takeover: false`, A instead gets `AddressInUse` at `lib.rs:316` and fails fatally.)
- **Sequence 2 (close + takeover while a third listener waits):** L1 holds `path` while L2 is below it in `HOLDS` (`self.bound == None`). L1 calls `hold.leave()` (`hold.rs:109-124`), raising `L2.signal.acquire = true`. Before L2 processes `turn()`, L3 (`takeover: true`) calls `hold::enter()`, raising `L2.signal.displaced = true` and making L3 the holder (`HOLDS = [L2, L3]`). When L2 runs `lib.rs:440-445`, line 440 clears `displaced` and `self.displace()` is a no-op (`self.bound` is `None`); line 443 then clears `acquire` and calls `self.bind(false)` despite `!self.hold.holding()`. If L2 has `takeover: true` (e.g. previously displaced) and L3 already published, L2 renames over L3's socket (displacing L3 via `look()` while L2 stays bound with `displaced` already cleared); if L2 has `takeover: false` and `!ever_bound` and L3 already published, L2 dies with `AddressInUse`; if L2 binds before L3 publishes, L2 stays bound without ever displacing because `displaced` was already cleared and `look()` returns early for non-holders (`lib.rs:334`).

**Actual vs. expected:** In Sequence 1, both listeners become displaced, neither accepts connections, and dead socket `inode_A` stays on disk permanently (B's `look()` only rebinds when `now.is_none()` at `lib.rs:353`). In Sequence 2, a non-holding listener publishes over the real holder or fails spuriously with `AddressInUse`. Expected: per LLP 1133.005 D2 (`llp/1133.005-a-local-listener.rfc.md:224-232`) and `host/listen/src/hold.rs:1-6`, within one process one listener holds the address at a time, `takeover` cleanly hands the address to the newcomer while displacing the older listener, and releasing the holder hands the address only to the listener that currently holds it.

**Verification and sibling sweep:** Verified by reading `host/listen/src/lib.rs`, `host/listen/src/hold.rs`, `host/listen/src/bind.rs`, `host/listen/src/watch.rs`, `host/listen/src/abi.rs`, and `host/executor/src/listen.rs`. Checked siblings: `host/listen/src/loopback.rs` binds exclusive TCP loopback ports with no `HOLDS` or `takeover` logic; `host/executor/src/listen.rs` delegates all path hold/bind logic to `exact-listen`.

**Suggested fix and regression test:** Serialize same-process hold checks with `bind::publish` per path (e.g., a per-path mutex or hold-gated publish helper) so a listener verifies `self.hold.holding()` inside the critical section before calling `bind::publish` and skips binding (emitting `Standing("waiting")` / staying displaced) if already displaced. In `Loop::turn` (`lib.rs:439-445`), drain the signal flags and reconcile against `self.hold.holding()`: if `!holding`, call `self.displace()` and never bind; if `holding && self.bound.is_none()`, call `self.bind(false)`. Add tests in `host/listen/src/tests.rs` covering (1) concurrent `Listener::open(..., takeover: true)` calls on the same path verifying the winning holder accepts connections and no orphaned dead socket remains, and (2) waking a waiting/displaced `Loop` when both `acquire` and `displaced` are set while `!hold.holding()`, verifying it neither steals the socket nor fails with `AddressInUse`.

### Siblings checked

host/listen/src/loopback.rs (exclusive loopback TCP bind, no hold/takeover); host/executor/src/listen.rs (thin ABI wrapper over exact-listen).
